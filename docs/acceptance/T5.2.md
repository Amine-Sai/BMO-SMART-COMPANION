# Acceptance Test T5.2: Pi UDP and HTTP Audio Streaming Transport

Status: PASS

## Overview
Implemented low-latency audio transport for the edge device (Raspberry Pi) and brain:
- **UDP Audio Streaming (`Pi -> Brain`)**:
  - `UDPAudioSender`: Packs 4-byte sequence header (`!I`) + 640 bytes 16 kHz mono `int16` PCM into 644-byte UDP datagrams. Slices/pads to `FRAME_SAMPLES` (320 samples).
  - `UDPAudioReceiver`: Implements `AudioSource`. Listens on UDP socket with 1 MB receive buffer, background daemon receiver thread, tracks received and dropped packets via sequence gaps, thread-safe frame queue with `read_frame(timeout_s)`.
- **HTTP WAV Transport (`Brain -> Pi`)**:
  - `pcm_to_wav_bytes` / `wav_bytes_to_pcm`: High-fidelity roundtrip conversions between mono `int16` PCM and standard WAV byte buffers.
  - `HTTPAudioServer`: Implements `AudioSink`. Threaded HTTP server serving `/tts/<utt_id>.wav` and `/tts/latest.wav`.
  - `fetch_tts_wav`: HTTP client fetching WAV replies and returning 1D `int16` numpy arrays.
- **Protocol Boundary**:
  - Zero MQTT involvement in audio streaming transport.

## Verification
- Interface compliance: `isinstance(receiver, AudioSource)` and `isinstance(server, AudioSink)`.
- 5.0 s (80,000 samples, 250 frames) UDP streaming verified with 0% packet loss (< 1% requirement) and exact sample reconstruction.
- 5.0 s HTTP WAV transport roundtrip verified with bit-identical sample equality (`np.array_equal`).
- Zero MQTT usage verified via static source inspection.
