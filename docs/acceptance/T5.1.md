# Acceptance Report: T5.1 Pi Client (MQTT + LCD + Speaker + Mic + ESP32 Bridge)

Status: PASS

## Summary
Implemented `edge/pi_client.py` and integration test suite `tests/test_t51_pi_client.py`.
The Pi client coordinates MQTT communication, face rendering on `BRAIN_SAY` and `HW_CMD` (`set_expression`), sound playback logging on `HW_CMD` (`play_sound`), servo command translation and ESP32 bridge logging on `HW_CMD` (`move_servo`), mute switch event publishing, and status telemetry.

## Key Capabilities Verified
1. **MQTT Broker Integration**: Authenticates as `pi` / `pi_insecure_dev_password` against `SimpleMQTTBroker` using `infra/passwords.example` and `infra/acl`.
2. **LWT & Heartbeat**: Sets LWT for `HW_STATUS` (`online=False, retain=True, qos=1`) and publishes `HwStatus(online=True, capabilities=["lcd", "speaker", "mic", "servos"])` via `publish_heartbeat()`.
3. **Face Rendering on Utterance**: Subscribes to `BRAIN_SAY`, updates `current_emotion`, generates frame via `render_face_frame(..., speaking=True)`, and appends to `spoken_utterances`.
4. **Hardware Command Handling**:
   - `set_expression`: updates emotion and renders non-speaking frame.
   - `play_sound`: tracks audio in `played_sounds`.
   - `move_servo`: formats command using `format_move_cmd`, sends to `ESP32ProtocolSimulator`, and records `(cmd, reply)` in `serial_log`.
5. **Mute Event Publishing**: Emits `HwEvent(kind="mute_switch", value=...)` on `HW_EVENT`.
6. **Telemetry Subscriptions**: Subscribes to and tracks `BRAIN_STATUS` and `VISION_STATUS`.
7. **Hygiene**: Strict compliance with no topic string literals outside `bmo_contracts.topics`, zero bloat, full type annotations, passing all Ruff and Vulture checks.
