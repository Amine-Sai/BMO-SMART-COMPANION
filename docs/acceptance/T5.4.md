# Acceptance Test Report: T5.4 Hardware Mute & Offline Fallback

**Task:** T5.4 - Hardware mute & offline fallback
**Status:** PASS

## Overview
EdgeMonitor monitors edge hardware status and hardware events over MQTT. It coordinates hardware mute switch state changes with `BrainStateMachine` and provides transparent fallback between edge and local audio sources and sinks.

## Verified Capabilities
1. **Hardware Mute Switch**:
   - `HwEvent(ts=1.0, kind="mute_switch", value=True)` transitions `BrainStateMachine` to `BrainState.MUTED`.
   - Halts audio capture: `monitor.muted is True`, `monitor.active_source is None`, and `monitor.read_frame() is None`.
   - Stops the active audio sink.
   - `HwEvent(ts=2.0, kind="mute_switch", value=False)` transitions `BrainStateMachine` back to `BrainState.IDLE`, sets `monitor.muted is False`, and restores `monitor.active_source`.

2. **Offline Fallback & Heartbeat Monitoring**:
   - Edge online heartbeats (`HwStatus(online=True, ...)`) route audio capture and playback to `edge_source` and `edge_sink`.
   - Explicit offline status (`HwStatus(online=False, ...)`) or heartbeat timeout expiry (`clock() - last_heartbeat > heartbeat_timeout_s`) switches `active_source` and `active_sink` to `fallback_source` and `fallback_sink` without disruption.

3. **MQTT Message Ingestion**:
   - Validates JSON payload strings and bytes dispatched from `HW_EVENT` and `HW_STATUS` MQTT topics.
